## 记录但未改动

- WebDAV 限流桶按路径划分，更换路径即可换桶；合并为单桶会在 `TRUSTED_PROXY_HOPS=0` 时让所有客户端共用一个额度，需要先决定取舍。
- `TRUSTED_PROXY_HOPS=0`（Compose 默认值，应用直接暴露时使用）下所有来源共用同一个限流桶，登录也是：全站合计每分钟 5 次、每 15 分钟 20 次登录尝试，任何人用完后其他人在窗口内无法登录。可以由自定义服务器把连接的对端地址传给限流逻辑来改善。
- 生产构建依赖访问 Google Fonts（`next/font/google` 的 Geist）；在无法访问的网络里构建会失败，改为随仓库提供字体文件可以消除这一依赖。
- 进入代理的请求在认证之前最多缓冲 34 MiB（此前为 10 MB）。这是让 32 MiB 的 AI 对话和配置导入可用的代价；并发连接总量仍由前置反向代理和 systemd 的内存上限约束。
- SFTP 上传仍先把整个表单体读入内存（上限 100 MB）；改为原始请求体流式上传可以去掉这部分内存占用。
- tar 回退方式的同步结果显示“0 个文件，0 B”，因为 tar 不输出传输统计。
- WebDAV 与 RFC 的差异（自动创建父目录、不支持目录 `COPY`、不保存自定义属性、锁不强制、不校验 `PROPFIND` 请求体）见 `docs/webdav-compatibility.md`；拒绝访问目前返回 422 而不是 403。
- 下载的 `Range` 头格式非法或单位未知时返回 416，RFC 9110 的做法是忽略该头并返回 200；真实客户端不会发送这类请求。
- 容器镜像以 root 运行并挂载 Docker 套接字，属于产品功能（管理本机容器）的前提。
- 安装脚本在未设置 `DOMAIN` 时取 `ip -4 addr` 的第一个全局地址作为 `SSH_WS_ALLOWED_ORIGINS` 和 Apache 的 `ServerName`。公网地址经 NAT 映射的云主机（网卡上只有内网地址）会得到内网地址，浏览器来源与之不符，终端的 WebSocket 会被拒绝，需要手工改 `.env`。

本批记录但未改动：

- 备份范围是否应自动包含安装目录之外的本地存储，需要负责人决定：自动纳入会让备份体积和耗时随网盘数据增长，而平台内发起的备份有 30 分钟的命令超时。“文件备份”模式目前完全不读取 `BACKUP_EXTRA_PATHS_JSON`。

- `backup.create` 作业失败后的作业级重试没有意义（记录已是 FAILED，无法再次认领）；定时备份已经把重试次数设为 1。
- 平台备份的异地对象键没有扩展名，内容类型为 `application/octet-stream`。
- 平台在 VPS 备份中途退出时，目标机上的 `/tmp/vch-backup-*.tar.gz` 不会再被清理。
- 恢复步骤的 Windows 版本把 `cmd` 的 `set` 与 POSIX 单引号路径混在一起，无法在 `cmd.exe` 中原样执行（没有 Windows 环境，未实测）。
- 标准（脱敏）配置导出包含告警规则的 Webhook 地址。这类地址通常带令牌；审计日志里已经只记录“是否配置”，而规则列表接口本身返回完整地址。是否在标准导出中清空，需要负责人决定。
- 配置导入直接写入设置表，不经过各项设置的取值校验；运行时设置读取时会把非法值标为 `invalid-database` 并回退，其余键没有这层保护。导入只对平台管理员开放。

- 导入不恢复 SSH 密钥的“创建人”，该字段只用于展示。
- Docker 部署没有 systemd，平台自检的四项服务检查恒为“状态暂不可读”（警告），Git 同步检查恒为警告。
- `src/lib/settings/schema.ts` 里设置键的联合类型和 `VALID_SETTING_KEYS` 数组是两份手工维护的清单。

本批记录但未改动：

- GitHub Actions 的 `test` 作业不运行 `i18n:key-check` 和 `verify:deploy-assets`，它们只在发版时的 `npm run verify` 里执行；缺翻译键的合并请求可以通过 CI。修改工作流文件需要令牌带 `workflow` 权限，本次没有改，建议负责人补上这两步。
- 自签证书的 HTTPS 网关（不填域名、用 IP）：签发链接前的健康检查会校验证书，自签证书永远通不过，所以这种方式启用后实际一直走中转。是否放宽取决于浏览器端如何处理证书错误和回退，结论见第 5 批的记录（不放宽）。
- 在“公网域名”里填 IPv6 字面量会在第一个冒号处被截断。
- 监控脚本只在安装 Agent 时写入节点，已安装的 Agent 要到重装或自动更新后才用上新脚本（Agent 需要 systemd，Alpine 节点本来就只能走 SSH）。
- 快速服务卸载并“删除数据”时，控制面进程在自身沙箱内删除宿主目录：目录里的内容可以删，目录本身是只读挂载下的挂载点，按内核规则删不掉。这一点想在沙箱里用挂载命名空间验证，命令被安全检查拦下，没有绕过，因此未经验证；请负责人在真机确认卸载是否会因此报错。
- 容器镜像里没有 `aria2c`，容器部署不能使用磁力／BT 中继下载；也不包含重置密码、重置双因素的脚本。
- Windows 部署脚本启动 Web 任务时没有关闭进程内 Worker，与独立的 Worker 任务同时运行两套。队列领取是原子的，功能上无碍；Linux 的 systemd 单元和容器入口都只保留一套，是否对齐由负责人决定（Windows 任务失败三次后不再重启，两套并存反而多一层保障）。
- Windows 直连网关一次只处理一个请求，一个大文件的传输期间其他请求（包括健康检查）都在排队。
- 预检只要求安装目录有 512 MB 空闲空间，而一次完整构建需要的远多于此。
- 服务器删除被依赖项阻止时，提示里列的是内部字段名（`files=12, scheduledTasks=1`）。
- 用自带的重置脚本修改的是名为 `admin` 的账号；该账号被改名或删除后脚本无法使用。

systemd 行为的出处：[systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)（`ReadWritePaths=` 中的路径不存在时，只有带 `-` 前缀才会被忽略；`SetLoginEnvironment=` 默认只在设置了 `User=` 等时才提供 `$HOME`；`ProtectSystem=full` 把 `/usr`、`/boot`、`/efi`、`/etc` 设为只读）。

| 存储节点名称里有 `/` 或 `\` 时，文件页总览中该节点的入口被拆成两段路径 | 点开显示“目录不存在” | 分组键里的分隔符替换掉 |
| 异地备份的 Secret Key 是唯一没有去掉首尾空白的凭据字段 | 粘贴时带上换行，之后每个请求的签名都不对，界面上看不出原因 | 保存前去掉首尾空白 |
| `/api/storage/direct-access` 的回退地址对所有驱动都指向 SFTP 下载接口 | 本机和 WebDAV 节点拿到的回退地址会被回答“不是 SFTP 节点”。界面只对 SFTP 节点使用这个接口，受影响的是 API 调用方 | 按驱动给出对应的下载接口 |
| 收藏和最近访问列表每一行单独做一次授权检查 | 每页最多 50 次查询 | 每页一次批量检查 |

本批记录但未改动：

- 有配额的授权在写入期间持有整个节点的配额锁，直到索引写完；等锁超过 30 秒或锁连接池耗尽时抛出的是未翻译的数据库错误（500）。锁模块在第 6 批，届时一起处理。
- 重命名、移动目录时，索引里的后代超过 10000 条会被拒绝。这个上限是逐行更新的年代定的，现在已是单条 UPDATE，可以在实测后放宽。
- SFTP 同步按远端原样记录文件名；末尾带空格或含反斜杠的名字经过路径规范化后会变成另一个名字，彻底删除这类条目时实际操作的是规范化后的那个路径。
- SFTP 目录暂时为空（例如磁盘没有挂载）时，同步会把其下的索引全部送进回收站，之后的同步不会自动恢复。
- 递归同步遇到读不了的子目录（如 `lost+found`）时，任务重试三次后整体失败。
- WebDAV 节点和只有 Agent 的节点没有缩略图；5000 万像素以下的隔行 PNG 和 GIF 仍然整幅解码（约 200 MB 以内）。
- 异地备份固定发送 `x-amz-server-side-encryption: AES256`，没有配置 KMS 的 MinIO 会拒绝这个请求头。
- `/files` 页面把存储节点的连接摘要（主机、端口、用户名、根路径、WebDAV 地址）发给所有有 `storage:read` 的用户，而 `/api/storage/nodes` 返回的是精简后的字段。
- 自签证书的直连网关（第 4 批遗留）：结论是不放宽健康检查。界面上的下载链接先到 `/api/storage/direct-access`，由它 302 到签名地址；浏览器在跳转后遇到证书错误没有回退的机会，放宽检查会把“走中转、能下载”变成证书错误页。自签网关只适合“直连”模式下已导入证书的用户，建议在界面上说明。
- 公开分享的下载不支持 Range（断点续传）；媒体库扫描在请求内同步执行；图床单次上传没有磁盘保留空间检查。
- 服务端动作把底层错误原文返回给用户，其中可能带服务器上的绝对路径（如 `EACCES … '/srv/…'`），只有具备写权限的用户能触发。
- `src/lib/files/tree.ts` 里的建树、序列化、搜索函数只被测试引用；收藏列表的游标翻页在特定排序下可能跳过一行；存储相关的 Zod 校验提示是英文。
- 页面（服务端组件）调用服务层时同样没有语言上下文，服务层生成的说明文字（如存储节点的连接摘要“本地存储：…”）在英文界面下预计仍是中文；媒体详情页为直连节点拼出的地址没有签名。这两点留到第 8 批读页面时确认并处理。
- 英文词典里还可能有其他机器拼接的句子，第 9 批用脚本整体扫描；两步验证恢复码接口的兜底提示是“启用两步验证失败”，第 7 批处理。
- 安装脚本和容器镜像都不安装 `7z`、`unrar`，文档里已注明这两种格式依赖外部命令。

出处：MinIO 未配置 KMS 时拒绝 SSE 请求头，见 [MinIO 服务端加密文档](https://docs.min.io/community/minio-object-store/operations/server-side-encryption.html) 和 [相关讨论](https://www.github.com/outline/outline/discussions/1601)。7-Zip 与 unrar 的输出格式来自在沙箱里实际运行 7-Zip 23.01、unrar 7.0.7 的结果（发行版软件包）。

- ITSM 出站工作器每 5 秒处理一个事件（每分钟 12 个）。钉钉自定义机器人每分钟最多 20 条、超过会被限流 10 分钟，这个节奏反而安全，没有改；`adapters.ts` 里有一条注释提到已经不存在的 `__setItsmFetch`。
- 多个工作进程同时运行时，同一个 Playbook 的第二次运行最多等锁 30 秒，之后按失败重试；第一次运行超过几分钟时，第二次可能在重试用完后失败。单个工作进程不会出现（它一次只处理一个 Playbook 任务）。
- `claimNextJob` 对每个待处理任务做一次关联计数来排序，任务很多时会变慢，目前的规模没有问题。
- 直连下载在启动时就为目标文件写索引（大小为空），下载失败后这一行会留下；下载链接没有路径时文件名由远端脚本决定，控制端拿不到。
- `assertPublicRdpHost` 把整个 `192.0.0.0/16` 都当作内网（实际只有 `192.0.0.0/24`、`192.0.2.0/24` 等几段是保留地址），偏严但无害；`isEncrypted` 的判断对含两个冒号的旧明文可能误判。
- 密码最小长度的设置没有和 128 的上限比较；运行时设置的校验错误里带英文的字段名。留到读设置页和接口时确认。
- 工单只改处理人或只改优先级时不写时间线；刷新间隔的选项文字是英文。两项都需要界面配合，列入前端阶段。
- 接口层的 Zod 校验提示普遍是英文，校验失败的摘要也是英文（“webhookUrl: …”“3 field(s) failed validation: …”）。这是接口包装层的统一行为，第 7 批读接口时一并评估。
- 没有语言 Cookie 的浏览器调用接口时，语言按 `Accept-Language` 判断（中文则中文，否则英文），而页面本身按平台默认语言显示，两者可能不一致。同样留到第 7 批。

### 第 7 批：其余全部 API 路由，以及使用中报告的上传卡死

读过：`src/app/api` 下此前没有读到的全部路由，包括 `admin`（公开状态页、工作器）、`alert-incidents`、`alert-rules`、`announcements`、`api-tokens`、`audit`、`auth`（两步验证、退出、WebSocket 与远程桌面票据）、`backup-schedules`、`backups`、`cost`、`dashboard`、`docs`（OpenAPI）、`downloads`、`health`、`identity-templates`、`itsm`、`monitoring`、`notifications`、`preferences`、`search`、`settings`、`tickets`、`users`，以及 `servers/[id]` 下的 `detect-os`、`reload`、`file-proxy`。至此 `src/app/api` 的路由全部读完。本批还包括一个使用中报告的问题：同时上传四个文件（其中两个超过 200 MB）后站点卡死。

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 分片上传的分片、合并出的完整文件、WebDAV 上传的请求体，默认都暂存在 `/tmp/vcontrolhub-media-uploads`。安装脚本生成的服务单元带 `PrivateTmp=true` 和 `MemoryHigh=640M`、`MemoryMax=768M` | `/tmp` 是内存盘的系统上（Debian 13 起默认如此），暂存的每个字节都是内存，并且计入 Web 服务的内存额度。一个文件在暂存区最多占自身大小的 2 倍（分片加合并文件），浏览器同时传两个文件：两个 200 MB 的文件就超过 640M，内核随即大幅放慢这个进程，整个站点卡住；到 768M 时进程被杀掉重启 | 暂存目录默认改到数据目录下（文件历史目录的上一级，安装脚本的布局里是 `/var/lib/<slug>/upload-tmp`），在磁盘上，并且 Web 与 Worker 都能读写；数据目录不可写时（开发环境、没有数据卷的容器）才回退到 `/tmp`。`MEDIA_UPLOAD_TMP_DIR` 仍然优先。部署文档与环境变量示例已补充 |

本批记录但未改动：

- 每个正在上传的分片在 Web 进程里有两份（代理层缓存一份，路由再读一份），浏览器同时传 2 个文件、每个文件 5 个分片并发时合计约 100 MB。改成流式写盘可以省掉一份，但要改动分片接口的校验方式；暂存改到磁盘之后这部分内存不再随文件大小增长，所以没有动。合并文件仍然先在暂存区生成：直接在云盘目录里合并的话，节点的配额锁要在整个合并期间一直持有，而现在的设计特意把合并放在加锁之前。
- 服务单元模板里的内存上限（Web 与 Worker 各 768M）没有改，模板本身注明要按机器调整。
- 接口作者自己写在校验规则里的英文提示还有约 130 条（存储 23、AI 19、服务器 13、Docker 12、Playbook 11、命令 9 等），以及表单提交在路由内部校验失败时的通用兜底提示。CSRF 校验失败的提示（“CSRF token validation failed”）也是英文，只在令牌 Cookie 丢失时出现。
- `PATCH /api/users` 调整账号类型和收窄权限是两次独立的写入，不在同一个事务里。
- 工单的标题、描述和回复没有长度上限，只受 1 MiB 请求体上限约束；上限要和界面的表单一起定，留到读页面时处理。
- 通知的“标为已读”每次都写一条审计记录；备份任务的标题和“Backup finished with status …”是保存下来的英文；流量概览接口和后台采样任务可能在同一个 5 分钟内各写一条本机采样。
- 临时文件代理（在目标服务器上起一个 Python 进程）在界面上已经没有入口，直连网关已经取代了它，可以考虑移除。
- 同步任务的“立即运行”在请求内同步执行（接口注释里说明了这一限制）；远程桌面票据接口的拒绝提示是默认的英文。
- 仪表盘分析接口里下载任务和图床两部分仍然分页读取，这两张表一周内的数据量很小。

出处：Debian 13 起 `/tmp` 默认是 tmpfs、默认最多占用一半内存，见 [Debian 13 发行说明 5.1.6 节](https://www.debian.org/releases/trixie/release-notes.en.txt)；`PrivateTmp=` 为每个服务挂载不与其他进程共享的 `/tmp`，并在服务停止时删除其中的文件，见 [systemd.exec(5)](https://manpages.ubuntu.com/manpages/focal/man5/systemd.exec.html)；超过 `MemoryHigh=` 后进程被大幅放慢、达到 `MemoryMax=` 后在单元内触发 OOM，见 [systemd.resource-control(5)](https://manpages.debian.org/systemd.resource-control)；tmpfs 中的数据计入创建它的控制组（`memory.stat` 的 `shmem`），见[内核文档 Control Group v2](https://docs.kernel.org/6.14/admin-guide/cgroup-v2.html)。用户服务器上实际触发的是哪一种情况（内存盘上的内存额度，还是磁盘上的 I/O 压力）没有在那台机器上确认。

## 真实环境边界

沙箱网络无法访问 `binaries.prisma.sh`、`fonts.googleapis.com`、`ifconfig.me` 以及各容器镜像仓库（docker.io、ghcr.io、lscr.io），因此快速服务的镜像没有实际拉取和运行，容器端口以各项目的官方文档为准：迁移用 psql 逐个执行 98 个迁移文件（没有经过 `prisma migrate deploy`，库里没有 `_prisma_migrations` 表），构建使用本地字体样式。Windows Agent 与 RDP、真实云厂商和 AI 提供商、Nextcloud／群晖／坚果云账号、手机浏览器均未实测。同步与 SFTP 的远端是本机 sshd，不代表各发行版和各版本 rsync 的全部组合。
