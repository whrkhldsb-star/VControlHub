# 按功能清单推进的改进记录

本记录用于多轮修改与最后统一验证，产品功能说明见[项目指南](project-overview-and-user-guide.zh-CN.md)。记录中的“已修改”只表示代码已经调整，不表示测试通过或已经部署。

## 第三轮：SSH 文件操作与回收站

本轮检查 SSH 文件面板、SFTP 路由／连接加载／路径授权和回收站列表，与前两轮分开记录。问题根据源码调用关系定位，未运行复现或测试。

| 问题 | 具体触发与根因 | 已实施的修改 |
| --- | --- | --- |
| Windows SSH 内嵌文件面板无法使用 | SFTP 复用 Linux SSH 加载器，Windows 在构造连接前被拒绝；旧服务层还直接读取服务器通用端口和账号 | 新增 SFTP 专用加载入口，Windows 使用绑定存储节点的 OpenSSH 配置；路径授权也使用同一连接及配置根目录 |
| 普通 Linux 账号首次打开失败 | 前端固定从 `/root` 开始，失败再访问 `/`，与普通成员的 home 限制冲突 | 列目录接口允许省略 path，由服务端返回账号对应的常规 home；Windows 使用绑定根路径 |
| 根目录上传被拒绝 | 前端去掉 `/` 的尾斜杠后提交空字符串，后端判为缺少目录 | 上传直接提交当前目录，路径拼接交给后端；尚未完成目录加载时不接受拖入上传 |
| 多批上传的进度更新错行 | 用整个进度列表的长度反推当前批次索引；下一批加入后，前一批的响应更新到后一批；清空 input 还可能影响原 FileList | 对 FileList 立即取快照，每个文件持有稳定 id，按 id 更新；完成提示只清理所属批次 |
| 旧目录操作完成后跳回 | 上传／删除／新建／重命名成功后无条件加载发起时的目录；旧错误也覆盖新目录 | 用当前导航目标判定是否刷新和显示错误；导航清空旧选择与编辑，失败后恢复显示目录的目标状态，卸载终止列表请求 |
| 目录边界解析不准确 | 尾斜杠、Windows 盘符写法及符号链接根目录使字面比较与远端路径不一致；直连 realpath 失败时曾继续猜测甚至返回原字符串 | 统一绝对路径比较，根目录和目标均使用远端解析结果；直连只对缺失路径回溯父目录，权限／连接错误及悬空符号链接直接报告失败 |
| 回收站授权与文件访问不一致 | 列表未应用工作区所有者／管理员的授权规则；无效路径授权被转成空前缀，可能扩大列表范围 | 与存储访问使用相同的工作区管理者判断及节点范围；无效授权不参与匹配，分页数量与数据共用范围 |

相关场景加入[路径验收清单第 2、3 节](path-walkthrough-checklist.md)，全部保持未勾选。未运行测试、类型检查、lint、应用构建或部署验证。Windows OpenSSH、Linux Agent 与直连 SSH 的实机行为留待统一验证；Linux 自定义 home 的自动发现不在本轮实现范围内。

## 第二轮：下载、同步与图片上传

本轮沿下载 API、后台派发器、下载列表分页、同步 CRUD／执行入口、图片分片工作池检查实际调用链；另核对工作区切换已通过布局中的作用域 key 重建上传及终端子树，因此没有重复改动这一机制。下列问题来自代码路径分析，尚未通过运行复现或测试验证。

| 问题 | 具体触发与根因 | 已实施的修改 |
| --- | --- | --- |
| 后续下载页面保留旧状态 | 加载更多后，刷新只查询第一页，再把其他旧行合并回来；后续页的删除、完成或失败长期不更新 | 按已展开页数重新读取，整体替换当前列表；串行处理加载与刷新，切换筛选终止旧请求，旧错误也不进入新筛选 |
| 下载取消覆盖终态 | 取消 API 不检查已结束状态，最终无条件按 id 更新；执行完成与取消并发时也能覆盖完成结果 | 已结束任务返回 409，已取消任务幂等返回；写入时仅更新 PENDING／RUNNING，保留并发产生的终态 |
| 下载失败却显示派发成功 | 执行器内部捕获错误并保存 FAILED 后正常返回，外层直接 completeJob | 正常返回后重新读取业务结果，FAILED／CANCELLED 对应 failJobTerminal，完整完成和仅派发分别记录 |
| 同机嵌套目录同步 | 仅比较两个原始路径是否相同，允许 `/data` 与 `/data/archive`，也不能识别 `/data/./` 等等价路径 | 共用路径整理和目录包含关系规则，覆盖界面、创建、编辑以及已有任务执行入口；执行拒绝写入失败记录 |
| 图片上传失败后的在途响应覆盖状态 | Promise.all 首个失败即返回，其余工作线程仍派发请求和更新状态；直接使用响应快照还会让进度随乱序响应倒退 | 失败后停止派发、等待所有工作线程结束再返回错误，合并并排序已确认分片形成单调进度 |

对应的待验证场景已追加到[路径验收清单第 4 节](path-walkthrough-checklist.md)。全部状态为“已修改，未测试”；未运行测试、类型检查、lint、应用构建或部署验证。源码差异审阅和文档生成不视为业务验证。

同步目录检查按节点记录及路径进行词法比较，不解析远端符号链接，也不识别不同记录背后的同一物理主机。下载取消的本轮修改针对终态覆盖，不宣称对所有远端进程退出场景作了实机验证。
