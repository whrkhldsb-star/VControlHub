## 记录但未改动

- WebDAV 限流桶按路径划分，更换路径即可换桶；合并为单桶会在 `TRUSTED_PROXY_HOPS=0` 时让所有客户端共用一个额度，需要先决定取舍。
- `TRUSTED_PROXY_HOPS=0`（Compose 默认值，应用直接暴露时使用）下所有来源共用同一个限流桶，登录也是：全站合计每分钟 5 次、每 15 分钟 20 次登录尝试，任何人用完后其他人在窗口内无法登录。可以由自定义服务器把连接的对端地址传给限流逻辑来改善。
- 生产构建依赖访问 Google Fonts（`next/font/google` 的 Geist）；在无法访问的网络里构建会失败，改为随仓库提供字体文件可以消除这一依赖。
- 进入代理的请求在认证之前最多缓冲 34 MiB（此前为 10 MB）。这是让 32 MiB 的 AI 对话和配置导入可用的代价；并发连接总量仍由前置反向代理和 systemd 的内存上限约束。
- SFTP 上传仍先把整个表单体读入内存（上限 100 MB）；改为原始请求体流式上传可以去掉这部分内存占用。
- tar 回退方式的同步结果显示“0 个文件，0 B”，因为 tar 不输出传输统计。
- WebDAV 与 RFC 的差异（自动创建父目录、不支持目录 `COPY`、不保存自定义属性、锁不强制、不校验 `PROPFIND` 请求体）见 `docs/webdav-compatibility.md`；拒绝访问目前返回 422 而不是 403。
- 下载的 `Range` 头格式非法或单位未知时返回 416，RFC 9110 的做法是忽略该头并返回 200；真实客户端不会发送这类请求。
- 容器镜像以 root 运行并挂载 Docker 套接字，属于产品功能（管理本机容器）的前提。
- 安装脚本在未设置 `DOMAIN` 时取 `ip -4 addr` 的第一个全局地址作为 `SSH_WS_ALLOWED_ORIGINS` 和 Apache 的 `ServerName`。公网地址经 NAT 映射的云主机（网卡上只有内网地址）会得到内网地址，浏览器来源与之不符，终端的 WebSocket 会被拒绝，需要手工改 `.env`。

本批记录但未改动：

- 备份范围是否应自动包含安装目录之外的本地存储，需要负责人决定：自动纳入会让备份体积和耗时随网盘数据增长，而平台内发起的备份有 30 分钟的命令超时。“文件备份”模式目前完全不读取 `BACKUP_EXTRA_PATHS_JSON`。
- 平台内发起的备份命令 30 分钟超时，VPS 远程备份命令 10 分钟超时；数据量大的实例会稳定失败，需要改用定时器在平台之外执行或调高上限。
- `backup.create` 作业失败后的作业级重试没有意义（记录已是 FAILED，无法再次认领）；定时备份已经把重试次数设为 1。
- 平台备份的异地对象键没有扩展名，内容类型为 `application/octet-stream`。
- 平台在 VPS 备份中途退出时，目标机上的 `/tmp/vch-backup-*.tar.gz` 不会再被清理。
- 恢复步骤的 Windows 版本把 `cmd` 的 `set` 与 POSIX 单引号路径混在一起，无法在 `cmd.exe` 中原样执行（没有 Windows 环境，未实测）。
- 标准（脱敏）配置导出包含告警规则的 Webhook 地址。这类地址通常带令牌；审计日志里已经只记录“是否配置”，而规则列表接口本身返回完整地址。是否在标准导出中清空，需要负责人决定。
- 配置导入直接写入设置表，不经过各项设置的取值校验；运行时设置读取时会把非法值标为 `invalid-database` 并回退，其余键没有这层保护。导入只对平台管理员开放。
- 配置导入失败时把 Prisma 的原始报错（含源码路径）返回给管理员界面。
- 导入不恢复 SSH 密钥的“创建人”，该字段只用于展示。
- Docker 部署没有 systemd，平台自检的四项服务检查恒为“状态暂不可读”（警告），Git 同步检查恒为警告。
- `src/lib/settings/schema.ts` 里设置键的联合类型和 `VALID_SETTING_KEYS` 数组是两份手工维护的清单。

本批记录但未改动：

- GitHub Actions 的 `test` 作业不运行 `i18n:key-check` 和 `verify:deploy-assets`，它们只在发版时的 `npm run verify` 里执行；缺翻译键的合并请求可以通过 CI。修改工作流文件需要令牌带 `workflow` 权限，本次没有改，建议负责人补上这两步。
- 自签证书的 HTTPS 网关（不填域名、用 IP）：签发链接前的健康检查会校验证书，自签证书永远通不过，所以这种方式启用后实际一直走中转。是否放宽取决于浏览器端如何处理证书错误和回退，留到第 5 批看完文件与播放器的调用方再定。
- 在“公网域名”里填 IPv6 字面量会在第一个冒号处被截断。
- 监控脚本只在安装 Agent 时写入节点，已安装的 Agent 要到重装或自动更新后才用上新脚本（Agent 需要 systemd，Alpine 节点本来就只能走 SSH）。
- 快速服务卸载并“删除数据”时，控制面进程在自身沙箱内删除宿主目录：目录里的内容可以删，目录本身是只读挂载下的挂载点，按内核规则删不掉。这一点想在沙箱里用挂载命名空间验证，命令被安全检查拦下，没有绕过，因此未经验证；请负责人在真机确认卸载是否会因此报错。
- 容器镜像里没有 `aria2c`，容器部署不能使用磁力／BT 中继下载；也不包含重置密码、重置双因素的脚本。
- Windows 部署脚本启动 Web 任务时没有关闭进程内 Worker，与独立的 Worker 任务同时运行两套。队列领取是原子的，功能上无碍；Linux 的 systemd 单元和容器入口都只保留一套，是否对齐由负责人决定（Windows 任务失败三次后不再重启，两套并存反而多一层保障）。
- Windows 直连网关一次只处理一个请求，一个大文件的传输期间其他请求（包括健康检查）都在排队。
- 预检只要求安装目录有 512 MB 空闲空间，而一次完整构建需要的远多于此。
- 服务器删除被依赖项阻止时，提示里列的是内部字段名（`files=12, scheduledTasks=1`）。
- 用自带的重置脚本修改的是名为 `admin` 的账号；该账号被改名或删除后脚本无法使用。

systemd 行为的出处：[systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)（`ReadWritePaths=` 中的路径不存在时，只有带 `-` 前缀才会被忽略；`SetLoginEnvironment=` 默认只在设置了 `User=` 等时才提供 `$HOME`；`ProtectSystem=full` 把 `/usr`、`/boot`、`/efi`、`/etc` 设为只读）。

## 真实环境边界

沙箱网络无法访问 `binaries.prisma.sh`、`fonts.googleapis.com`、`ifconfig.me` 以及各容器镜像仓库（docker.io、ghcr.io、lscr.io），因此快速服务的镜像没有实际拉取和运行，容器端口以各项目的官方文档为准：迁移用 psql 逐个执行 98 个迁移文件（没有经过 `prisma migrate deploy`，库里没有 `_prisma_migrations` 表），构建使用本地字体样式。Windows Agent 与 RDP、真实云厂商和 AI 提供商、Nextcloud／群晖／坚果云账号、手机浏览器均未实测。同步与 SFTP 的远端是本机 sshd，不代表各发行版和各版本 rsync 的全部组合。
