## 本轮修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| Next.js 会缓冲 `src/proxy.ts` 匹配到的每个请求体，只把前 `proxyClientMaxBodySize`（默认 10 MB）字节交给路由，且请求不报错 | WebDAV `PUT` 超过 10 MB 的文件被截断保存并返回 `201`（15 MB 与 200 MB 的文件都只存下 10,449,920 字节）；SSH 文件面板上传超过 10 MB 必定 500；AI 对话（32 MiB）、配置导入（32 MiB）、图片与分片上传（20 MiB）达不到各自声明的上限，表现为“请求体不是有效 JSON”或表单解析失败 | `/api/webdav/**` 与 `/api/servers/[id]/sftp/upload` 移出代理匹配范围，请求体直接流式写入；SFTP 上传路由自行做代理原有的 CSRF 校验，两条路由自行补上代理统一添加的响应头；其余路由的上限提高到 34 MiB；WebDAV `PUT` 实际收到的字节数少于 `Content-Length` 时拒绝且不落盘；`/api/storage/local` 单次请求超过上限时返回指向分片上传的 413 |
| 代理在响应上设置的头会覆盖路由自己设置的同名头 | 生产环境中，文件预览、媒体、图床、公开分享和 WebDAV 给用户上传的 HTML／SVG 设置的 `Content-Security-Policy: sandbox` 被页面策略替换：文档以应用同源身份渲染（脚本仍被页面的 nonce 策略拦截，但失去了沙箱隔离；不支持 `strict-dynamic` 的旧浏览器会按 `'self'` 放行同源脚本） | 代理不再给 `/api/` 响应设置页面策略，返回用户内容的路由保留自己的策略 |
| Next.js 对以 `/` 结尾的路径返回 308 | litmus、cadaver、davfs2 这类以 `MKCOL /dir/` 访问集合的 WebDAV 客户端在第一步失败 | 自定义服务器在进入 Next 之前去掉 `/api/webdav` 路径的结尾斜杠 |
| `MKCOL` 目标已存在时返回 409 | 与 RFC 4918 不符，客户端把“已存在”误判为“父目录缺失” | 返回 405 并带 `Allow` |
| `LOCK` 把客户端在 `If` 头里给出的任意令牌写回 XML 响应 | 响应体可被注入标记 | 只回显格式正确的 `opaquelocktoken:` |
| 限流窗口保存窗口内的每一次尝试，被拒绝的也不例外 | 持续刷请求时，同一来源之后的每次检查都更慢；Redis 后端每次都把整个窗口取回 | 每个桶只保留最新的 `maxRequests + 1` 个时间戳（内存与 Redis），判定结果与重试时间不变 |
| SFTP 上传的写入错误以普通 `Error` 抛出 | 目录不存在、权限不足、磁盘已满一律显示为 500“上传失败”；发送前失败的上传行一直停在“上传中” | 错误按 404／403／422／502 归类，面板显示服务器给出的原因，发送前失败的行标记为失败 |
| Agent 任务认领在“过期任务积压超过单次清理量”时，用 `"createdAt" + … > now()` 判断任务是否仍可执行 | 列里存的是 UTC 时间，而 `now()` 带时区；数据库会话时区为 Asia/Shanghai 时，剩余时间不足 8 小时的任务都被判为过期，新任务要等积压清完才会下发；UTC 以西的时区则把过期任务判为可执行 | 与 `now() AT TIME ZONE 'UTC'` 比较，和库内其他原始 SQL 一致 |
| `deploy/__tests__/preflight.test.ts` 的升级脚本用例里，`ip` 的替身输出一个裸地址，而安装脚本解析的是 `ip -4 addr` 的 `inet …` 行 | 替身从未被匹配，脚本转而请求 ifconfig.me：该用例只在能访问这个外部服务的机器上通过，在隔离网络里失败 | 替身输出脚本实际解析的格式，并断言渲染出的 Apache 配置使用该地址 |
| 单元测试只在工作线程里加载 bcrypt 原生模块 | 最后一个持有它的线程退出后，之后的线程再加载就报 `Module did not self-register`；哪些文件失败取决于执行顺序。基线上同样的 8 个文件按四种顺序运行，分别失败 6、7、6、2 个 | 新增 `src/test/global-setup.ts`，在 Vitest 主进程里全程持有该模块 |

## 记录但未改动

- WebDAV 限流桶按路径划分，更换路径即可换桶；合并为单桶会在 `TRUSTED_PROXY_HOPS=0` 时让所有客户端共用一个额度，需要先决定取舍。
- `TRUSTED_PROXY_HOPS=0`（Compose 默认值，应用直接暴露时使用）下所有来源共用同一个限流桶，登录也是：全站合计每分钟 5 次、每 15 分钟 20 次登录尝试，任何人用完后其他人在窗口内无法登录。可以由自定义服务器把连接的对端地址传给限流逻辑来改善。
- 生产构建依赖访问 Google Fonts（`next/font/google` 的 Geist）；在无法访问的网络里构建会失败，改为随仓库提供字体文件可以消除这一依赖。
- 进入代理的请求在认证之前最多缓冲 34 MiB（此前为 10 MB）。这是让 32 MiB 的 AI 对话和配置导入可用的代价；并发连接总量仍由前置反向代理和 systemd 的内存上限约束。
- SFTP 上传仍先把整个表单体读入内存（上限 100 MB）；改为原始请求体流式上传可以去掉这部分内存占用。
- tar 回退方式的同步结果显示“0 个文件，0 B”，因为 tar 不输出传输统计。
- WebDAV 与 RFC 的差异（自动创建父目录、不支持目录 `COPY`、不保存自定义属性、锁不强制、不校验 `PROPFIND` 请求体）见 `docs/webdav-compatibility.md`；拒绝访问目前返回 422 而不是 403。
- 下载的 `Range` 头格式非法或单位未知时返回 416，RFC 9110 的做法是忽略该头并返回 200；真实客户端不会发送这类请求。
- 容器镜像以 root 运行并挂载 Docker 套接字，属于产品功能（管理本机容器）的前提。
- 安装脚本在未设置 `DOMAIN` 时取 `ip -4 addr` 的第一个全局地址作为 `SSH_WS_ALLOWED_ORIGINS` 和 Apache 的 `ServerName`。公网地址经 NAT 映射的云主机（网卡上只有内网地址）会得到内网地址，浏览器来源与之不符，终端的 WebSocket 会被拒绝，需要手工改 `.env`。
