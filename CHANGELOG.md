# Changelog

All notable changes to VControlHub are documented here. Versions follow Semantic Versioning.

## [Unreleased]

### Fixed

- CI "Verify shared UI components" raced the theme transition: `check-ui-showcase.mjs` runs axe right after switching the theme `<select>`, and components transition their colors for 150ms — on slower CI runners axe sampled mid-transition frames and reported color-contrast violations for final colors that pass (verified by injection-timing experiment; e.g. `rgb(136,148,157)` is the dark/light mix). The check now runs under `reducedMotion: "reduce"` (globals.css collapses transitions) with a settle wait, and `ui-upgrade.spec.ts` gets the same hardening around its runtime theme toggle.
- Local dev hydration stalled on every page when the dev server was addressed as `127.0.0.1`: Next 16 treated the HMR websocket as a cross-origin dev-resource request ("Blocked cross-origin request … from 127.0.0.1"), which silently blocked client bootstrap — pages rendered SSR HTML but never hydrated, so no client fetches fired and client-only states (lists, live monitoring) stayed on their loading spinners forever. `allowedDevOrigins` now covers the loopback hosts.
- Sidebar branding hydration mismatch: `AppSidebar` (client) read env-backed `getAppName()`/`getPublicLabel()` directly — SSR rendered `APP_NAME` ("whrkhldsb") while the client bundle fell back to "VControlHub", a per-page hydration mismatch (dev overlay "Issues"). `SidebarLoader` now resolves both server-side and passes them as props.
- `/ai` collapsed to a one-character-wide column whenever no conversation was open: the `dynamic()` loading stubs of `AiProviderPanelLazy`/`AiSettingsPanelLazy` are `h-40 w-full` blocks that render in-flow (including in SSR HTML), and as flex-row children of the AI workspace they consumed the whole row, squeezing the chat column to zero width — the empty-state heading rendered one glyph per line. The stubs now render nothing: the real panels are modal overlays with no in-flow space to preserve, and their chunks still preload on workspace mount.
- SFTP media streaming/thumbnails were broken for DIRECT-managed nodes: the credential select behind `mediaStreamItemSelect` did not include `hostKeySha256`, so the routes' `enforceHostKeyPin` failed host-key verification on every connection (even for pinned nodes). The pin column is now selected on both the storage node and its server.
- Live RDP sessions were torn down by unrelated server-row writes: `rdpEndpointHash` included `updatedAt`, so agent heartbeats and cost auto-sync (which bump `@updatedAt` without touching the endpoint) invalidated the hash and disconnected every session within one 5s revalidation cycle. The hash now covers only connection-bearing fields; enabled/OS state is still rechecked on every revalidation via `getRdpServer`.
- RDP bridge hardening: concurrently open client clipboard streams are capped (16) instead of growing without bound; the 20-session cap is enforced at ticket-claim time (unauthenticated sockets can no longer squat it — the upgrade gate keeps 3× headroom for in-flight handshakes and ticket-less sockets are dropped after 10s).
- `fetchWithPinnedDns` now returns the full validated address set in undici's `all:true` lookup mode instead of only the first record — providers with multiple A records regain connect-time failover while every returned address still passed the blocklist/public-IP validation.
- Account-lockout expiry cleanup (`isAccountLockedAsync`) deletes through the same per-key mutation chain as failure recording, so a concurrent failed-login write can no longer be wiped by a stale expired-entry delete.
- VPS backup API routes serve their localized 500 copy again (`vpsBackupApi.errorTriggerFailed` et al.) — the dedup sweep had let these fall through to the guard's generic "Operation failed", orphaning five translation keys. Business-rule 4xx statuses are unchanged.

### Added

- RDP clipboard sync (rdclient/mstsc parity): the `/rdp` bridge accepts Guacamole clipboard streams — strictly `text/plain`, base64-bounded blobs, stream-index tracking and a ~1.5 MB per-session cap — and the browser client syncs both directions (Ctrl+V sends the local clipboard into the desktop; remote copies land in the local clipboard when the browser allows it). Opt out with `RDP_ENABLE_CLIPBOARD=false`; drive/printing/pipe channels stay blocked. Optional remote audio passthrough is available behind `RDP_AUDIO_ENABLED=true` (off by default; guacamole-common-js plays it natively).
- Remote desktop client toolbar: fullscreen (Fullscreen API), fit-to-window ↔ actual-size zoom toggle (with scrolling at 1:1), a Ctrl+Alt+Del secure-attention button, and a connected-time counter — previously the surface was display + keyboard/mouse only.
- RDP session policy joins the runtime settings surface: `runtime.rdpIdleTimeoutSec` and `runtime.rdpMaxSessionSec` (`RDP_IDLE_TIMEOUT_SEC` / `RDP_MAX_SESSION_SEC`), applied per connection. Defaults (0/0) keep a healthy session alive as long as its browser — matching the SSH idle default — while an independent 10-minute dead-transport floor still reaps crashed browsers on half-open sockets.
- Windows VPS billing: create/edit forms now carry the same cost fields (auto-sync, monthly amount, currency, provider) as Linux nodes, persisted through `createServerProfile`/`updateServerProfile` and shown on the Windows node card's edit form, so cost pages cover the whole fleet.
- `src/lib/security/pinned-fetch.ts` — `fetchWithPinnedDns`: undici Agent with a custom connect-time lookup that resolves DNS once, refuses rebind-to-private addresses, and pins the verified IP for redirects; wired into the four outbound SSRF surfaces (AI provider HTTP, quick-service adapters, cloud-billing adapters, storage direct-access).
- Session-revocation epoch (`User.sessionEpoch`): session tokens embed the epoch they were minted against and stop verifying once it advances. 2FA enable/disable retires every existing session of the account (re-minting the acting browser's cookie), and the new `POST /api/auth/signout-all` plus an "退出所有设备" panel on `/account/security` give users a real sign-out-everywhere primitive — previously a leaked cookie stayed valid for its full TTL (up to 30 days) with no revocation path short of a password change.
- `src/lib/http/request-origin.ts` — cross-site form-post detection (Sec-Fetch-Site / Origin / Referer host comparison) used to close the login-CSRF window on `/api/login` and `/api/auth/2fa/verify-login` without affecting non-browser clients.
- Migration `20260923104907_session_epoch_and_fk_indexes`: adds `User.sessionEpoch`, backfills+enforces NOT NULL on legacy-nullable vps-backup columns, drops the obsolete global `quick_services_slug_key` unique (superseded by `(instanceKey, slug)` — it blocked installing the same app slug on two nodes), adds the long-missing `file_entries.deleteBatchId` column and the missing FK indexes (`ai_hosted_actions.messageId/requesterId`, `deployment_runs.templateId/commandRequestId`, `sync_jobs.sourceServerId/targetServerId`, `servers.sshKeyId`). This also reconciles accumulated drift between `schema.prisma` and the migration history — deployments using `prisma migrate deploy` were missing several schema-declared changes.
- `storageAccessDeniedCopy` — `assertStorageAccess` denials now carry stable machine codes (`no_access`, `quota_exceeded`, …) rendered as zh/en copy at the API boundary, replacing the English `reason` strings that bypassed translation at 10+ call sites.
- Domain-owned hardening dictionaries (`storage-hardening-api.ts`, `ssh-hardening-api.ts`, `ops-hardening-api.ts`) wired into the service-translation barrel.
- Job retention: the maintenance-worker tick now prunes FAILED/CANCELLED jobs older than 30d across all types and caps COMPLETED rows (keepLatest 25) for the 19 high-frequency job types that had no self-cleanup; downloads/playbook workers prune terminal rows on both success and failure paths.
- Windows Agent support: Windows nodes can now switch to Node Agent mode and connect a PowerShell agent (Windows 10 / Server 2016+) for monitoring metrics and command execution. The agent speaks the same authenticated poll protocol as the Linux Python agent, runs as a SYSTEM scheduled task (`VControlHubAgent`) installed via a one-time elevated PowerShell one-liner (`prepareWindowsAgentInstall` + `GET /api/agent/v1/bootstrap`), reports metrics in the shared `===SECTION===` format, executes jobs through `cmd /c chcp 65001` (UTF-8), heartbeats long jobs, and clamps 32-bit exit codes to the protocol's 0–255 range. See `docs/windows-agent.md`.
- Windows node cards: agent status chip, install-command panel with clipboard copy, and realtime probing via the agent metrics channel once connected.
- `docs/windows-agent.md` — Windows agent architecture, install/uninstall flow, and security properties.
- Windows support for development, build, and production run: platform-aware relay download temp dir (`%TEMP%`), file-version blob root (`%PROGRAMDATA%\VControlHub`), and hub-host Docker endpoint (named pipe / `DOCKER_HOST` with `unix://`、`npipe://`、`tcp://` parsing); Windows bsdtar exclude handling for local archive streaming.
- Hub-host monitoring and traffic stats on Windows: CPU via `os.cpus()` window diff, per-process top list and TCP connection count via PowerShell/`netstat`, interface counters via `Get-NetAdapterStatistics` (shared sampler with short cache, also used by the traffic route).
- `docs/windows-development.md` — Windows environment setup, production run, and per-feature platform boundaries.
- CI `test-windows` job (windows-latest): typecheck + lint + unit tests + build, guarding cross-platform regressions.
- Cross-platform CLI backup/restore entry points: `npm run backup` / `npm run restore` wrap the Node runners (`scripts/backup.mjs` / `scripts/restore.mjs`, sharing `scripts/lib/backup-common.mjs`); artifact formats, exit codes, and log prefixes match the bash scripts, so Windows and Linux share one command surface.
- `src/lib/ssh/server-target.ts` — the single "load server → require enabled → build SSH params" step with typed errors and canonical `backend.ssh.*` copy (zh/en), plus a credential-free variant for scope descriptors.

### Changed

- Empty states unified: the shared `EmptyState` always renders an icon tile (default file glyph; page-specific icons keep their tile), and the hand-rolled plain-text empty blocks on tickets, announcements and VPS status now ride the same component (announcements / VPS status use the boxed variant).
- Raw system errors surfaced in the UI are localized before display: new `describeKnownError` maps Node fs/socket error codes (ENOENT/EACCES/ECONNREFUSED/ETIMEDOUT/ECONNRESET) to zh/en summaries (new `commonError.*` keys) while keeping the raw message as a monospace detail line — applied to the shares file picker's sync/load errors and the files browser list error (replacing the bespoke localized-prefix format).
- Docker page copy is fully localized: the always-visible scope warning renders from the `dockerPage.scope.warning` / new `dockerPage.scope.remoteWarning` keys instead of the server descriptor's English string, and the Docker-unavailable error notice uses the localized `dockerPage.error.fetch` key instead of the raw API message.
- Page content width unified across the console: the pages that overrode `PageShell maxW` with narrower containers (`/notifications`, `/announcements`, `/account/password`, `/account/security`, files sub-pages recycle-bin/sync/webdav/recent-downloads, `/itsm`, ticket detail, files preview) now share the default `max-w-7xl` shell with every other page, so navigating between sections no longer jumps the content column around (`/account/security` keeps an inner reading width; the public status page is unchanged).
- Traffic page header rides the shared `PageHeader` actions slot: refresh/auto-refresh controls sit on the header row and the bottom divider spans the full content width instead of stopping under the title.
- Alert-rule cards standardized on the shared `data-card` surface with the action buttons inlined in one row (`data-action-button` warning/success/danger variants) instead of a custom elevated card with a vertically stacked button column.
- Dashboard "核心资源/运维队列" stat panels now end on the same grid row (queue grid is 2×2 with the notification card spanning the full row) instead of leaving a hole under the left panel; `StatCard` accepts an optional `className` to support the spanning card.
- Change-password page's security-tips aside uses the standard card chrome (`data-card`) instead of a one-off `rounded-3xl` surface.
- Windows VPS add/edit forms restyled to match the Linux sections: RDP credentials now render in the same titled, bordered section pattern (`RdpCredentialFields` + new shared `ServerCostFields`) instead of a flat field list, closing the "bolted-on" look of the later-added Windows pages.
- RDP session lifetime is no longer hard-coded (previously 30 min idle / 4 h absolute): the bridge reads the two new runtime settings per connection and only enforces what is configured.
- SSH idle reaper now honors `runtime.sshIdleTimeoutSec` per terminal (0 = never idle-disconnect), fixing the gap where the settings page advertised "0 means never" but an env-only `SSH_WS_IDLE_TIMEOUT_MS` (default 30 min) still closed terminals; the legacy env value remains only as the fallback when the settings DB read fails at boot. The setting applies to newly opened terminals without a service restart.
- System-health git probes (`rev-parse`, `ls-remote`) and `systemctl is-active` checks run through async `execFile` — `/api/system-health` no longer blocks the Node event loop for up to ~5s per command under concurrent requests.
- `POST /api/files/operations` evaluates one permission gate per request (action-specific `storage:write`/`storage:delete` on a session-only route guard) instead of running the declarative `storage:read` check first and re-checking permissions in the handler.
- VPS backup worker prunes old COMPLETED records after every successful manual backup run when the server's schedule defines `retentionDays` — manual "back up now" records were previously never pruned unless a scheduled run happened to execute later.
- Worker-runtime health read is capped (`take: 500`, freshest-first) so a heartbeat-retention gap cannot turn the admin workers endpoint into a full-table scan.
- SSR waterfalls parallelized: cost-summary (5 reads via `Promise.all`), status page (`getAllUptimeData` + `getPublicStatus`), and ticket detail (single query + locally derived participant permissions instead of a second round-trip).
- FileVersion blob cleanup rewritten: `purgeAllFileVersionBlobs` uses a single query plus bounded-concurrency unlink, and permanent directory deletion now purges its versions' blobs first, preventing orphaned blob files.
- Runtime hardening round: ssh-ws-proxy handshake validation + graceful shutdown (prisma disconnect, 15 s exit timer, `uncaughtException` → exit 1); notification WebSocket server caps connections (200), heartbeats (30 s) and enforces a `bufferedAmount` ceiling; advisory-lock pool sets a 10 s connection timeout; storage-node reads enforce `teamId: null` isolation; SSH host-key pinning is enforced on all five client paths.
- Naming unification: package name is `vcontrolhub`; systemd unit templates renamed `whrkhldsb-*.service.example` → `vcontrolhub-*.service.example` (the installer's legacy-name fallback is removed); CI database name unified to `vcontrolhub_ci` (matching `vcontrolhub_release` in the release workflow); `.env.example` defaults (`APP_NAME`/`APP_SLUG`/`PG_DB_*`), `scripts/ci-local.sh`, the rclone-alist unit description and stale doc references follow the same slug.
- Agent capability declarations now list `["metrics","command"]` on both platforms — the previous `"file"` entry was a placeholder with no implementation behind it.
- API error copy is fully translated: the last hard-coded English messages (VPS backup deletion/path containment, app-source catalog fetch, archive exclusion validation) moved to zh/en service translations, and the api-copy audit baseline is now zero findings.
- All `tsx`-driven npm scripts now auto-load `.env` (`--env-file-if-exists=.env`), fixing `npm run db:seed` & co. on fresh checkouts on every platform.
- Archive listing (`/api/files/archive-list`) parses both GNU tar and bsdtar `-tv` output, and reads zip archives via bsdtar on Windows (no `unzip` needed); `.gz` extraction now decompresses with Node `zlib` instead of the `gunzip` binary.
- Route catalog / RBAC audit / verification scripts normalize path separators, producing identical output on every OS (previously the catalog generated zero routes on Windows, which broke `next build`); rbac-audit output lists are sorted for deterministic diffs.
- `verify:deploy-assets` runs through a cross-platform wrapper (explicit skip on Windows) so `npm run verify` completes everywhere.
- One platform abstraction: `src/lib/runtime/platform-paths.ts` now also exports `NULL_DEVICE`, `findExecutable`, `hubHostDockerSocketMount()`, `tempRoot()` and the live-read `isWindows()`; a parallel draft module was merged in and deleted.
- Password-auth SSH commands on Windows run over the bundled ssh2 client in-process (Windows ships no `sshpass`); bounded output, timeout/cancel codes, and host-key pinning match the sshpass transport, and tests can pin either transport explicitly.
- Backup/restore argv planning is spec-driven per platform (`backup/platform-runner.ts`); backup drills verify gzip integrity and PostgreSQL format in-process via Node `zlib` instead of `gzip -t` / `head` shell pipelines. aria2 binary resolution searches PATH plus platform install roots (with `ARIA2_BIN` override) instead of hard-coded `/usr/bin`.
- One shell-quoting implementation: six local `shellQuote` copies (three textual variants of a shell-injection guard) now import `@/lib/shell-quote`.
- One SSH server loader: quick-service docker, docker compose, and SFTP previously each inlined the lookup with three different failure shapes (422/400/500) for the same condition; all resolve through `server-target.ts` with typed errors.
- API-facing raw `Error` throws converted to typed errors — VPS backup record deletion (404/409/400 instead of 500), quick-service remote docker and catalog adapters, archive exclusion validation — so clients receive real status codes and messages.
- Frontend consistency: the image-bed page rides the global toast system (its page-local FloatingToast with private state/timer is deleted); sparkline and diff-review colors resolve from design tokens (zero raw palette classes remain); Spinner/Notice can no longer fall back to English labels in the zh locale; seven pure presentational components dropped needless `"use client"`; inline loading standardized on `InlineLoading`.
- **Security hardening sweep**: the forced password-change flag can no longer be cleared without actually setting a new password (the "skip for now" server action is removed); delegated `user:manage` holders can only grant roles/permissions they hold themselves and can never assign the `admin` role, and resetting/disabling a platform administrator is reserved for global team managers; storage-node grants in the permission panel are quarantined to the actor's own team for non-global actors; SSH terminal/SFTP/storage transports now enforce host-key pinning fail-closed like the command path; the Direct Gateway installer whitelists root-path/bind characters against systemd-unit injection; `apiCatch` never echoes raw non-AppError messages to clients regardless of fallback status; the 2FA login stage counts failures into the account-lockout bucket (the password stage no longer clears it early) and verifies under bounded JSON reads; login burns a dummy bcrypt compare for unknown usernames; the notification WebSocket no longer accepts session tokens via the URL query string; ITSM inbound / 2FA verify-login / agent poll bodies are read through the bounded streaming reader.
- **Performance/reliability sweep**: file-version snapshots stat before reading (no more whole-file buffering into memory on overwrite); VPS backup offsite uploads use a 30-minute idle-timeout budget instead of a 30s total abort; WebDAV DELETE/MOVE rewrite the file index with one batched statement per operation; media stream/thumbnail run a single ACL check per request; content-search scopes tombstone lookups to the searched nodes and batches remote greps; `.gz` extraction enforces a 1 GiB decompressed-output cap; copy operations pre-check ACLs per directory instead of per child; quick-service docker/ss/port probes are async (no more event-loop stalls in the API route); SSH command timeouts escalate SIGTERM→SIGKILL and collect output in O(n); keyboard-interactive only answers password-shaped prompts; local docker engine responses are capped at 32 MiB; compose bulk actions collapse to one CLI call; alert webhooks carry 10–15s timeouts; AlertRule match-state persistence is CAS-guarded; AI daily ops scans schedule in `APP_TIME_ZONE` and skip when a recent successful scan exists; AI streaming timeouts are idle-based (long responses from slow providers are no longer truncated at 90s); scheduled-task consecutive-failure detection reads structured run status instead of matching English prefixes in `lastResult`; Windows monitoring collectors are async with short caches and SSE sampling is shared across connections; media library scans page deterministically by cursor.
- **Frontend sweep**: switching languages no longer tears down live SSH terminal sessions or discards unsaved permission-panel edits (`t` removed from data-effect dependencies via refs); SSH file rows and terminal tabs are keyboard-operable (Enter/Space/arrows); the files module rides the global toast system; toast/notice entrance animations actually exist now (Tailwind 4 `@theme` keyframes instead of dead `animate-in` classes); backups/share pages format dates and errors through locale-aware helpers; notification and global-search layers use z-index tokens; users page uses the shared Pagination component; file delete uses the shared ConfirmDialog and refreshes without a full page reload; job action labels derive from structured fields instead of `title.split(" ")`.
- **Dedup round (import service)**: `upsertById` joins `upsertByIdWithSecondaryUnique` in `import-executors-helpers`; the nine remaining importers that hand-rolled the existence-check → createMany(skipDuplicates) → per-row update scaffold (command templates, quick services, playbooks, alert rules, announcements, snippets, servers, storage nodes; ssh keys via the secondary-unique variant) now share one counting/skip implementation.
- **Dedup round (frontend)**: the four file-list view variants declare their props once (`file-list-view-props.ts`) instead of re-declaring `ToastFn`/`EntryGuard`/`FolderGuard` and a ~15-field bundle per file; the delete/move/rename row forms share a `useActionStateNotifications` hook for the notify-once success/error plumbing; docker UI stats type `ContainerStats` aliases the API's `DockerContainerStats` instead of re-declaring it; 2FA enable/disable share `refreshedSessionResponse` for the epoch-bump cookie re-mint; pagination range copy is unified on `common.pagination.range` ("显示 {start}–{end}，共 {total} 条") with the dead `operationTasksPage.pagination.*` keys deleted and ai-ops migrated onto the common keys.

### Fixed

- Two interrupted-refactor regressions from the dialog/round consolidation: `ConfirmDialog` now renders as the TR-022 R10 mobile bottom sheet (`UI_OVERLAY_SHEET`: `items-end`/`sm:items-center`/`overflow-y-auto`, sheet panel chrome) like the other quick-service dialogs — the shared-component migration had silently reverted the uninstall/app-source-delete confirms to centered modals; and the operation-tasks list shows the unified range summary again instead of the divergent "显示第 x-y 项" copy.

- Windows nodes never fall into the Linux-only SSH paths anymore: `/api/servers/monitor` returns an explicit agent-offline (AGENT mode) or Linux-only (DIRECT mode) error instead of surfacing `buildSshParamsFromServer`'s rejection as a "connection failed" message, and batch-command targets on Windows fail with "no SSH fallback channel" instead of a misleading missing-password/host-key error when the agent goes stale between approval and execution.
- `/api/agent/v1/bootstrap` is registered in the RBAC audit's intentional public list (per-server bearer token auth, like `/api/agent/v1/poll`) and counted in the OpenAPI spec test; the stale "Windows rejects AGENT mode" schema test now asserts the new accepted-by-design behavior.
- README auto-metrics counted 0 pages / 0 API route files on Windows: the script's path predicates only matched `/` separators; both separators are now matched (55 pages / 185 routes regenerate identically on every OS).
- **Production custom server failed to boot** (CI `E2E public smoke` + `DAST baseline` both failed at "Start production custom server"): `src/server.ts` read `app.getUpgradeHandler()` *before* `await app.prepare()`, and Next's custom-server API throws `prepare() must be called before performing this operation` until the underlying server exists — `main()` rejected and the process exited 1 before it ever bound a port. The upgrade handler is now read after `prepare()`, and `src/__tests__/server-boot-order.test.ts` asserts the ordering against Next's real contract so a future refactor cannot reintroduce a boot-time exit that no typecheck or unit test would see.
- Login lockout mutation chain (`rate-limit.ts`) leaked a map entry per username: `recordLoginFailureAsync` serialized read-modify-write through a `Map` keyed by username but never removed entries, so spraying distinct usernames grew it without bound. Entries are now dropped as soon as their operation settles (guarded so a queued successor keeps the chain), keeping the map to in-flight keys only.
- Pinned host-key fingerprints silently read as `null` in the quick-service docker and docker-compose remote loaders (their prisma projections never selected `hostKeySha256`); the unified loader selects it, so host-key pinning works for those paths.
- VPS backup download paths on Windows: containment used POSIX string prefixes against native `path.resolve` results and always reported "escapes storage root"; now uses `path.relative`.
- Windows path handling across unit tests (platform-native expectations); Linux installer/restore-script tests skip explicitly on Windows instead of failing with `spawn bash ENOENT`.

## [0.1.0] - 2026-08-06

### Added

- VPS, SSH terminal, storage, backup, deployment, monitoring, alerting, ticket, AI, and team-management workflows.
- One-command lifecycle installer with install, update, health-check, backup, and complete uninstall actions.
- PostgreSQL migrations, independent durable workers, RBAC, audit logging, 2FA, API tokens, and bilingual UI.

### Changed

- Split browser, server-page, and backend-service translations to reduce browser and long-running process bundles.
- Hardened tenant boundaries, SSH onboarding, backup recovery, deployment idempotency, and release packaging.

### Security

- Added CSRF protection, rate limits, encrypted credentials, host-key pinning support, safe path handling, and dependency audit gates.
