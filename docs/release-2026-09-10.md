# Release preparation — 2026-09-10

This release includes the September 7–8 audit fixes and UI work, plus the
September 10 monitoring and dependency updates. The user explicitly authorized
deployment and production service restarts on September 10.

## Additional improvements

- Monitoring validates both HTTP and streamed payloads before rendering.
- Late HTTP snapshots cannot replace newer streamed metrics; obsolete streams
  cannot update a page after visibility changes or unmount.
- Initial HTTP requests time out, retaining a usable retry path.
- Silent streams fall back to polling after 15 seconds. Background tabs close
  their stream and reconnect on return; manual-only preferences disable SSE.
- Monitoring controls use the shared toolbar, action buttons and toggle state.
- Settings section actions are outside the interactive disclosure summary.

## Dependency security

The September 10 audit supersedes the previous no-known-vulnerability result.
It identified advisories affecting Next.js/Sharp, Nodemailer, js-yaml and Vitest.
Selected updates preserve the existing major versions:

| Package | Previous installed | Target |
| --- | --- | --- |
| Next.js / eslint-config-next | 16.2.12 | 16.3.4 |
| Sharp | 0.35.3 | 0.35.4 |
| Nodemailer | 9.0.3 | 9.1.1 |
| Vitest / coverage-v8 | 4.1.9 | 4.1.11 |
| js-yaml | 4.3.1 | 4.3.2 |

Dependencies are installed and tested in an independent directory. The active
production dependency tree is left intact until the coordinated release swap.
Lockfile generation required npm 11 because npm 10 hit an Arborist peer-tree
exception. A subsequent clean install with the host's ordinary npm 10.9.8
succeeded (802 packages installed); the final audit reports zero known
vulnerabilities. Native AVIF/PNG conversion and local mail rendering passed.

## Release process

- Verify the full test suite, build, lint, dependency audit and browser flows.
- Use production public branding values for the isolated build, retaining the
  isolated database and credentials for build-time validation.
- Verify production migration status (66 migrations; schema up to date).
- Take a PostgreSQL custom-format backup and back up runtime configuration.
- Compare build-input digests before promoting the verified artifacts.
- Stage `.next`, `dist` and `node_modules` before stopping services. Preserve
  previous hashed static assets for already-open browser tabs.
- Stop Next, Worker and SSH WebSocket services together, swap the three trees,
  start services and run smoke checks. Restore the old trees if promotion fails.
- Keep backups and previous artifacts for manual rollback. No automatic database
  restore is performed, avoiding loss of writes made after the backup.

Promotion and smoke-failure rollback have been exercised with temporary fixture
directories and mocked services. This does not substitute for post-release
production health checks.
