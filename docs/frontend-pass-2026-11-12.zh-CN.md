# 前端整理记录（2026-11-12 起）

审查（`docs/review-2026-11-10.zh-CN.md`）结束后的前端阶段：先处理妨碍使用的地方，再统一说法和画法，然后清理重复代码。界面的整体风格不变，沿用 `docs/ui-system.md` 的设计系统。改动在分支 `feat/frontend-20261112` 上（基于审查分支）；第 1、2 部分已由所有者合并到 main（#87），之后的部分没有合并。没有部署。

## 第 1 部分：使用逻辑

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 编辑带 Webhook 的告警规则会被拒绝 | 保存下来的 Webhook 地址不会发给页面（页面只知道“已配置”），所以编辑表单提交的是渠道列表、不带地址。而接口的更新规则要求“只要渠道里有 Webhook 就必须带地址”，于是这类规则改任何一项（阈值、冷却时间、通知对象）都会被拒绝，除非把地址重新输入一遍；表单上也没有任何说明 | 更新时不再只看请求本身：地址取“这次提交的”或“规则里已有的”，两者都没有才拒绝。表单在已有地址的规则上说明“留空则继续使用，填写则替换” |
| 告警规则接口的每个答复都带着数据库里的整行 | 一是 Webhook 地址（通常含令牌）出现在列表、创建、修改、启停的每个答复里，而页面刻意不显示它；二是答复的字段与页面使用的不同，页面从接口刷新一次之后，“Webhook 已配置”的标记就消失了 | 页面和接口共用一个输出形状（`src/lib/alert/rule-dto.ts`）：只说明是否配置了 Webhook，不带地址。审查第 1 批记过“规则列表接口返回完整地址”，这一条随之改变；标准配置导出里是否保留地址仍由所有者决定 |
| 数字输入框一清空就自己填回去 | 告警规则的阈值、持续时间、冷却时间、升级时间，备份保留的两项，Playbook 步骤的重试次数和超时，预算的告警阈值，共 9 处：输入框直接绑定数字，选中“30”删掉想改成“45”，框里立刻又变回 30（或变成 0） | 新增公共组件 `NumberInput`：输入过程中保留正在输入的文字，离开输入框或按回车时显示实际生效的数值。9 处全部改用它，并加了一条约定测试防止旧写法再出现 |
| 表单被拒绝的原因显示在看不到的地方 | 新建下载任务被拒绝时只弹一条几秒后消失的提示；成本页的条目对话框、删除确认、预算、云账单账户也是如此，其中预算和账单账户在必填项为空时点击按钮没有任何反应；Playbook 创建表单的错误显示在几屏之上的表单顶部 | 原因显示在所提交的表单里、按钮旁边，修改表单后消失；确认对话框的失败显示在对话框内。必填项为空时说明缺的是哪一项 |
| 成本页的两个表单没有字段名称 | 预算和云账单账户的输入框只有占位文字，一输入就看不到是什么字段；告警阈值那一格只显示一个“80”。币种在一处显示“人民币”，另一处显示“CNY”。汇总卡片的第三列标题与卡片标题相同，都是“当月汇总”，而且选了别的月份还叫“当月” | 每个字段都有名称，币种统一显示名称，第三列改为“按分类”，卡片标题改为“月度汇总”。页面上的主按钮只留“新增条目”一个 |
| 首页点一下卡片就弹出“详情” | 在卡片上任意位置点击（包括选中文字后松开鼠标）都会弹出对话框，里面是卡片的静态副本：按钮点了没有反应，页面上每个 id 都出现两次 | 去掉这个对话框。点击卡片只做卡片自己的事 |
| 首页调整组件顺序只能用鼠标拖 | 键盘和触摸屏无法调整顺序；被隐藏的组件没有卡片可拖 | “编辑布局”改为一个按顺序排列的列表，每个组件有上移、下移和显示开关；鼠标拖动卡片仍然可用 |
| Playbook 的开关按钮两种状态都写着“启用 / 停用” | 看按钮不知道点下去是启用还是停用，结果提示是“启用状态已切换” | 按钮写将要做的事（“停用”或“启用”），结果写做了什么（“已停用「名称」”） |
| 编辑告警规则时提交按钮写着“创建规则” | 编辑和新建用的是同一个表单，按钮名称没有区分；表单的错误提示在表单顶部，而按钮在几屏之下 | 编辑时按钮是“保存修改”；错误提示移到按钮旁边 |
| 通知中心“只看未读”在没有未读时是一片空白 | 看不出是没有未读，还是没加载出来 | 显示“所有通知已读”和“查看全部通知”；未读通知在尚未加载的更早记录里时，说明还有几条 |
| 任务中心的类型筛选选过一次就没有别的选项 | 选项取自当前列表里出现的类型；选了一种之后列表里只剩这一种，下拉框里除了“全部”就没有别的可选 | 打开页面以来见过的类型都保留在选项里 |
| 知识库检索框按回车没有反应，没有命中时界面不变 | 只能点按钮；检索不到内容时只弹一条“命中 0 条”的提示 | 回车即检索；结果区写明命中几条，没有命中时说明可以怎么做。切换知识库时先清空上一个知识库的文档列表 |
| 审计列表的详情只有被截断的一行 | 内容长的记录在页面上无法读全 | 点击详情打开整条记录：时间、级别、来源、操作者，以及每一项附加信息的完整内容 |
| 顶栏和快捷键列表在所有系统上都显示“⌘K” | Windows 和 Linux 的键盘没有这个键 | 按设备显示：苹果系统显示 ⌘K，其他显示 Ctrl K |
| 上传任务区在文件全部暂停时仍写“正在上传 1 个文件” | 与列表里的“已暂停”矛盾 | 暂停的文件单独计数：“已暂停 1 个文件”“正在上传 2 个文件，已暂停 1 个” |
| AI 对话页的三处 | 对话记录加载失败时，页面显示的是“发送消息开始对话”，和一段还没说过话的对话没有区别。模型下拉框里有“搜索”和“手动输入模型 ID”两个输入框，其实是同一份文字，在一个里输入另一个也跟着变；点别处或按 Esc 都关不掉。代码块的“复制”点了没有任何反应，浏览器拒绝复制时也一样；回复还在输出时，中文界面里这个按钮写的是 “Copy” | 加载失败时说明记录没有加载出来，并给出“重试”。下拉框只留一个输入框：既筛选，也可以使用列表里没有的 ID（列表末尾出现“使用「…」”，没有任何匹配时按回车即用），点别处或按 Esc 关闭。复制按钮显示“已复制”或“复制失败，请手动选中复制” |

验证：单元测试 991 个文件、8,449 条用例全部通过；需要数据库的测试 92 个文件、282 条通过、1 条跳过（它需要一个由 `prisma migrate` 建出来的库）；类型检查、lint、词条检查、接口提示审计、文档检查、权限审计、路由检查通过；生产构建成功。在这份构建上用 Chromium 跑端到端测试：公开页面 15/15，登录后的流程 15/16（1 条需要这里没有安装的 WebKit），业务流程 50/51（下载任务一条需要外网 DNS，这个环境没有），整站界面 95/95，CI 没有运行的三个用例文件 19 条通过；另有逐项的浏览器检查 28/28（告警规则、成本页、首页布局、审计、AI 对话页等）。这次验证里改了两条端到端用例：Playbook 一条原来在找旧的按钮文字“启用 / 停用”；客户删除与恢复一条在机器负载高时会失败（删除当前所选的客户后页面会重新挂载，把刚展开的“已删除的客户”又收了起来），改为等恢复按钮稳定出现。

这一部分记录但未改动：

- 首页的布局偏好保存的是“可见组件的顺序”。以后新增的组件，对保存过布局的账号来说与“被隐藏”无法区分，默认不显示。要区分需要给偏好增加一个“已隐藏”字段，涉及偏好接口和十来个测试，目前没有新增组件，暂不改动。
- 通知的删除没有确认也不能撤销。通知本身只是提醒，对应的事件仍在审计和告警记录里，没有加确认。

这一部分顺带发现并修复的缺陷（不属于前端）：

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| Linux Agent 在刚开始执行命令时收到停止信号，命令会被留下继续运行，也没有任何结果上报 | 服务停止或重启（systemd 发来 SIGTERM）恰好落在“命令进程已经启动、Agent 还没开始等待它”的那一小段时间里，Agent 直接退出：命令没有人结束，Hub 收不到结果，只能等租约到期后记为“结果未知”。这是一条单元测试在机器负载高时偶发失败暴露出来的；按 0 到 3 毫秒的间隔逐档发送停止信号，旧代码每次都能复现 | 这段时间里收到的停止信号先记下，进入等待后立即处理：结束命令、上报结果（退出码 143），然后退出。组装结果期间收到的停止信号同样先记下，结果照常上报。新增一条按间隔逐档发送停止信号的测试。Agent 的版本号没有改：已安装的 Agent 要拿到这个修复，需要所有者决定是提升版本号（在线的 Agent 会自动更新）还是重新安装。Windows Agent 没有检查这一点 |
| 存储节点“立即检测”的一条单元测试偶发失败 | 测试在失败提示出现后立刻断言按钮已恢复可点，而按钮要等这次操作结束才恢复 | 测试改为等按钮恢复 |

这一部分记录但未改动：

- 聊天记录里以“❌ ”开头的错误消息和“⚡ 执行：…”一类的工具调用行：这些前缀是程序识别消息类型用的，而且已经存进了历史消息，保留。

## 第 3 部分：可维护性

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 远程节点的内容搜索漏掉一类文件（缺陷） | “搜索文件内容”在本地节点和远程节点（SFTP）各有一份文件类型清单。远程那份是写死在 grep 命令里的 43 个扩展名，早已和本地清单不一致：没有扩展名的文件（Dockerfile、Makefile、README、.env、.gitignore 等）以及 .gradle、.dockerfile 等几种扩展名，本地节点搜得到，远程节点搜不到 | 远程命令的清单由本地清单生成，两边始终一致。新增测试在同一组文件上分别按本地和远程方式搜索，结果必须相同；旧命令下这条测试失败 |
| 同一件事有几份实现 | 下载速度的格式化（下载页自己算 B/s、KB/s，结果和全站的格式化函数不同）；链接类型的说明（新建下载表单和任务行各一份，词条也各一套）；提示消息回调的类型（7 个文件各自声明，有的不含“警告”）；终端快捷键的默认列表（两份完全相同）；健康页和节点状态页的 `tt` 包装函数（`t` 本身就会填充占位符）；没有语言上下文时的占位符填充（两份） | 各留一份：速度用全站的 `formatBytesPerSecond`；链接类型、提示回调类型（`ToastFn`，由提示组件导出）、快捷键列表、占位符填充各用一个共享实现；删除 `tt`，直接用 `t` |

## 前端阶段小结

改动都在分支 `feat/frontend-20261112` 上，每部分一个提交；第 1、2 部分已由所有者合并到 main（#87），之后的部分没有合并。界面的整体风格没有变，按 `docs/ui-system.md` 的设计系统整理，新的约定写进了 `docs/ui-system.md` 和约定测试。

这一阶段顺带发现并修复的缺陷：

1. 编辑带 Webhook 的告警规则会被拒绝；告警规则接口在每个答复里带出 Webhook 地址（第 1 部分）。
2. Linux Agent 在刚开始执行命令时收到停止信号，命令被留下继续运行、没有结果上报（第 2 部分）。
3. 远程节点的内容搜索漏掉没有扩展名的文件和几种扩展名（第 3 部分）。
4. 审批页在自己提交的命令上给出服务器会拒绝的审批表单；告警正文和事件详情里写着规则的内部代码（第 4 部分）。
5. 流量中心把流量整形用的虚拟网卡 ifb0 当成主网卡，首屏和流量历史一直是 0 B/s（第 7 部分）。
6. 新建 Playbook 时步骤名称输入框被挤成 26 像素宽，看不见输入的内容（第 9 部分）。
7. 通过 `http://<IP>` 访问时（IP 直连安装），文件上传、移动、发起部署、SSH 文件管理器上传和 AI 对话都因为浏览器没有 `crypto.randomUUID` 而失败（第 10 部分）。
8. 启用或停用 Playbook 会把它的链路重试清零；接管或修改一个停用的 Playbook 会把它重新启用（第 13 部分）。

记录但未改动、需要所有者决定的事项（详见各部分）：

1. Agent 停止信号的修复要让已安装的 Agent 拿到，需要提升 Agent 版本号（在线的 Agent 会自动更新）或重新安装；Windows Agent 没有检查同样的问题（第 2 部分）。
2. 后台进程写进数据库的整句文字（定时任务的上次结果、后台任务的失败原因、媒体上传的错误）有中有英，要随页面语言显示需要改成存代码和参数，涉及数据格式（第 2 部分）。
3. 首页布局偏好只保存“可见组件的顺序”，以后新增的组件对保存过布局的账号默认不显示；要区分需要给偏好增加“已隐藏”字段（第 1 部分）。
4. 标准配置导出里是否保留告警规则的 Webhook 地址（第 1 部分）。

其余“记录但未改动”的条目（快捷服务目录里的表情图标、通知删除不加确认等）是有意保留的，原因写在各部分里；第 2 部分保留的聊天消息前缀已在第 10 部分去掉。

Windows 上的单元测试以 CI 为准，这里只在 Linux 上运行过。
